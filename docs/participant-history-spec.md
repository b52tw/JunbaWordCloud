# JunbaWordCloud：參與者歷史互動與日期頁控制規格

> 狀態：需求已確認，待實作與測試  
> 適用分支：`fix/topic-archive-guardrails`  
> 部署原則：只在 `junba-wordcloud-staging` 開發與驗收；正式 Worker `junba-wordcloud` 不得因本功能而變更。

## 一、核心決策

1. 參與者歷史互動紀錄必須有實際存檔資料才顯示，不建立空白或虛構紀錄。
2. 參與者以同一支手機、同一個瀏覽器的匿名識別碼辨識，不以小名作為帳號或唯一識別。
3. 小名僅為顯示名稱，可匿名；同一小名可能由不同參與者使用。
4. 更換手機、瀏覽器或清除網站資料後，不保證能取回原紀錄。介面應清楚提示這項限制。
5. 主持人對每一筆歷史日期頁分別控制「開放互動／暫停互動」，不是只控制目前活動的總開關。
6. 參與者只能查看有存檔且主持人開放的歷史日期頁；主持人暫停該日期頁後，參與者仍可依產品決策查看唯讀內容，但不得投稿或按讚。
7. 只有主持人可以暫停／恢復歷史日期頁、清空當前活動及刪除歷史封存。

## 二、參與者端

### 我的歷史互動

- 入口設於參與者投稿頁。
- 使用瀏覽器持有的隨機參與者識別碼查詢自己的互動紀錄。
- 僅列出此識別碼確實投稿或按讚，且已完成保存的歷史活動。
- 每筆顯示活動日期時間、題目、本人投稿詞語、本人按讚紀錄及當時文字雲摘要。
- 不得因小名相同而混合不同手機的紀錄。
- 不向參與者暴露其他人的個人識別碼或私人紀錄。

### 再次互動

- 參與者可由歷史日期頁進入該主題的互動頁。
- 日期頁為開放狀態時，允許投稿及按讚。
- 日期頁為暫停狀態時，互動 API 必須拒絕投稿及按讚，前端同步顯示暫停訊息。
- 重新開放後，該日期頁恢復互動。
- 再次互動應建立新的互動輪次或獨立活動資料，不可覆寫原始歷史快照。

## 三、主持人端

歷史主題管理列表以日期時間排序，提供日期區間查詢。每筆歷史資料顯示：

- 日期時間與主題題目
- 投稿數、詞語數、按讚數
- 日期頁狀態：開放／暫停
- 開放互動、暫停互動操作
- 查看內容及刪除封存（需明確確認）

主持人可獨立切換每一個日期頁的狀態。切換某一日期頁不得影響其他日期頁或目前正在進行的活動。

## 四、資料與安全要求

- 參與者識別碼應由伺服器安全產生並以 HttpOnly、Secure（HTTPS）及適當 SameSite Cookie 保存；不可只依賴可由頁面腳本任意讀寫的 localStorage 值。
- 投稿與按讚事件須記錄所屬活動／日期頁、參與者識別碼、事件類型、內容及時間。
- 歷史快照須保留原始資料；重新互動資料與原始快照分開保存。
- 歷史頁的開放狀態必須由伺服器端 API 驗證，不能只靠前端按鈕隱藏。
- 暫停歷史日期頁時，所有該頁的投稿及按讚 API 均須拒絕操作。
- 不可將參與者識別碼或主持人管理憑證放入公開網址、QR Code 或一般頁面文字。
- 本功能只在 Staging 測試；不可修改正式 Worker、正式 Durable Object Namespace 或正式資料。

## 五、驗收條件

1. 手機 A 投稿後，重新掃描同一活動連結，仍可看到手機 A 的歷史互動。
2. 手機 B 即使輸入與手機 A 相同的小名，也看不到手機 A 的個人紀錄。
3. 沒有投稿或按讚紀錄的參與者，不顯示不存在的歷史活動。
4. 主持人可依日期區間找到已封存主題。
5. 主持人暫停日期頁後，該頁投稿與按讚 API 均失敗並顯示暫停原因。
6. 主持人重新開放日期頁後，參與者可繼續互動。
7. 暫停或恢復某一日期頁，不影響其他日期頁及目前活動。
8. 重新互動不覆蓋原始快照。
9. 參與者不能執行暫停、恢復、清空或刪除。
10. Staging 與正式環境的 Worker、DO Namespace 及資料完全隔離。
